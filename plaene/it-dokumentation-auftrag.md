# Unterlagen für eine IT-Abteilung — Anforderungen des Betreibers (23.09.2026)

Anlass: Eine IT-Abteilung hat Zugang zum Repository verlangt. Der Betreiber will das NICHT.
Stattdessen: Unterlagen als PDF und das Angebot eines Penetrationstests.

## Inhalt
* Alles, was das System kann (Funktionsumfang).
* Alle Sicherheitsmaßnahmen.
* Alles, was eine IT-Abteilung zur Überprüfung braucht (Architektur, Datenflüsse,
  Mandantentrennung, Rechte, Protokollierung, Datensicherung, Betrieb, Schnittstellen,
  Datenschutz).
* Das Angebot eines Penetrationstests anstelle des Repository-Zugangs.

## Form (wörtlich vom Betreiber)
* „ohne nebensätze" — kurze Hauptsätze.
* „ohne kosten" — keine Preise, keine Aufwände in Geld.
* „ohne firmenbezeichnung im kopf oder fuß".
* „keine hinweise die sich lesen wie eine versionshistorie" — kein „seit", kein „neu",
  keine Daten von Änderungen, keine Beitragsnummern, keine Runden.

## Reihenfolge (Betreiber 23.09.2026)
Erst alle anderen offenen Punkte fertig, DANACH die PDFs — die Unterlagen beschreiben den
Stand, der dann ausgeliefert ist. Die Acronis-Wiederherstellung ist verschoben.

## Lehre aus der Landingpage-Analyse (`plaene/landingpage-analyse-23-09-2026.md`)
* Keine Formulierung, die eine rechtliche Garantie suggeriert.
* Nutzen zuerst, Technik danach („Nachträgliche Änderungen werden erkennbar" vor „Hash-Kette").
* Zahlen und Aufzählungen einheitlich (keine abweichenden Modulzahlen).

## Grundsatz
Jede Aussage im PDF ist am Code oder am Betrieb belegt (Fundstelle in einer internen
Belegliste, die NICHT ins PDF geht). Keine Behauptung ohne Messung.
